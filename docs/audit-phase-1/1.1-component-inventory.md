## Critical Findings

### FINDING-1.1-A (Critical — Liability / Data Exposure)
**File:** `components/SessionHistory.tsx` (line 116) and `app/api/sessions/route.ts` (lines 25-26)
**Issue:** The component renders the numerical `hire_probability` (`{s.hire_probability}% hire probability`) directly in the user-facing session list. Additionally, the API returns this value as an integer. Per the non-negotiable rules in `CLAUDE.md`:
> "`hire_probability` is computed deterministically via `calculateNormalizedScore()` in `lib/rubric-researched.ts`. It is stored in `debriefs.debrief_data` and `debriefs.reasoning` but **never shown in the UI**. Only the 4-bucket recommendation badge is shown."
**Impact:** Potential liability risk; user sees deterministic internal score.
**Fix Required:** Remove `hire_probability` display from `SessionHistory.tsx` and exclude from API response in `app/api/sessions/route.ts`. Keep only `hire_recommendation` (Strong Hire / Hire / Borderline / No Hire).

### FINDING-1.1-B (Medium — Component Completeness)
**File:** `components/JDFallback.tsx`
**Issue:** Not fully audited; no separate test case executed.
**Fix:** Inspect in a follow-up cycle if needed.
