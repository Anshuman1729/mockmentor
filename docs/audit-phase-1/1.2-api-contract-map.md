## Critical Findings

### FINDING-1.2-A (Critical — Data Exposure / Liability)
**File:** `app/api/sessions/route.ts` (lines 25-26)
**Issue:** The GET endpoint selects `(d.debrief_data->>'hire_probability')::int AS hire_probability` and returns it in the JSON response. Per `CLAUDE.md` rules, `hire_probability` must never be exposed to clients. The UI (`SessionHistory.tsx`) then renders this value.
**Fix:** Remove `hire_probability` from SELECT and from response payload.

### FINDING-1.2-B (Medium — Missing Auth)
**Files:** `app/api/sessions/[sessionId]/route.ts`, `app/api/interview/question/route.ts`, `app/api/interview/answer/route.ts`, `app/api/interview/debrief/route.ts`
**Issue:** Several core interview endpoints do not enforce Clerk authentication (`auth()` check). This could allow session hijacking or unauthorized debrief generation if session IDs are guessed.
**Fix:** Add `await auth()` checks where appropriate, or rely on session-level authorization.

### FINDING-1.2-C (Medium — No OpenAPI / Contract Schema)
**Observation:** There is no `openapi.yaml` or JSON Schema defining contracts. All contracts are implicit from TypeScript interfaces.
**Recommendation:** Generate an OpenAPI spec in `docs/` during Phase 1.4.
